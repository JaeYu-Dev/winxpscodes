# v0.1.7 — SP3 pool-provenance checkpoint

Date: 2026-08-09

## Scope
This version does not claim a new Public-Key-Only break. It narrows the next Windows-side support-bound problem to the provenance of residual bytes in the KSecDD gather buffer and records a new V24 address-reuse candidate without over-promoting it.

## Carried-forward confirmed reduction from v0.1.6
The KSecDD materials consumed by the modeled first-key path are observations of one persistent 80-byte ratchet:

`X_{t+1} = VLH(X_t, P_t)`

`M_t = C_t XOR KS_{X_{t+1}}[0:256]`.

Therefore `M1..M6` are not six independent kernel roots. Their joint image is controlled by one starting state `X0`, sequential gather inputs `P1..P6`, and the already-reduced caller-side startup family.

## New V24 observation
The eight post-gather frame captures contain the pointer-like sequence:

`e1337008, e1379008, e137f008, e138e008, e12cc008, e134d008, e1379008, e137e008`.

Cycle 2 and cycle 7 repeat `0xe1379008` exactly. All values end in `0x008`, consistent with but not yet proving an XP x86 page+8 pool-payload interpretation.

Finding F009 records this as a strong OPEN candidate.

## Important negative discipline
The following inference is explicitly forbidden until machine-code provenance is closed:

`same candidate address -> same residual bytes -> zero fresh entropy`.

The correct implication requires both exact working-buffer identity and absence of an intervening writer at each relevant residual byte.

## Updated main bottleneck
For the kernel side, characterize:

`fresh_dimension(X0, P1..P6)`

with special attention to the actually hashed 0x258-byte prefix, not the full 0xE00 allocation capacity.

For each hashed byte not explicitly written by the SP3 gather builder, establish one of:
- `ZERO/FRESH`: known zero provenance;
- `SELF`: value descends from an earlier KSecDD allocation/state;
- `FOREIGN`: value descends from an unrelated allocator owner;
- `DERIVED/EXPLICIT`: value is written by a known machine-state source.

Only `FOREIGN` last-writer degrees that survive into the first-private-key image count as new irreducible roots.

## Immediate next actions
1. Prove or falsify that the V24 `...008` values are the 0xE00 `pbWorkingBuffer`/free-argument addresses in shipped SP3 machine code.
2. Reconstruct the SP3-native byte write mask over `[0,0x258)`; do not transplant SP1 offsets where the observed SP3 QSI order/layout differs.
3. Compare cycle-2 and cycle-7 unwritten hashed bytes if matching snapshots are recoverable.
4. Recompute the reachable-image model after provenance classification; do not assign entropy from buffer width or observed byte variability alone.

## Break status
`|R_C| < 2^128` remains unproved. The positive route survives only if the remaining `X0` and FOREIGN/DELTA ancestry can be reduced to a searchable joint image below generic secp256k1 ECDLP.
