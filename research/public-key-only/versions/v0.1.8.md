## Promoted findings

### F010 — CGR64 second-round local is SELF history

The second RSAENH provider transition within one 64-byte `D640` invocation reuses the same `[ebp-0x18]` local. Recovered exact write-set work found no reinitializing store before the second `SystemFunction036` call. Therefore the second round adds no independent 160-bit stack-prehistory root.

Promoted claim: `C-015 -> CONFIRMED MACHINE-DATAFLOW`.

### F011 — validated KSecDD pool width and 24-byte direct provenance gap

The direct VLH pool is `0x258 = 600` bytes, not the full `0xE00` allocation capacity. Recovered pinned long-gather work narrows the direct allocation-history region before the first QSI contribution to 24 bytes.

Important: 24 bytes is a provenance width, **not** a 192-bit entropy claim.

Added claim: `C-038`.

### F012 — class-05 SHA-1 projection

`SystemProcessInformation` class 05 contributes a captured `0xDC8 = 3528` byte region that is SHA-1 projected to a 20-byte downstream value. Therefore the local class-05 boundary has image <= `2^160`.

A strong partial-write candidate remains: the first `0x1b8` bytes parse as one valid Idle-process record, while the following bytes do not parse as the next ordinary SPI header. However, exact XP SP3 `ExpGetProcessInformation` compiler-split cold blocks are not yet closed, so “the rest is untouched tail” remains OPEN.

Added claims: `C-039` confirmed, `C-040` open.

### F013 — registry Seed correction

Recovered exact-SP3 work falsifies universal zero-state initialization. An existing 80-byte registry Seed is read; zero state is only the missing-Seed branch.

Added claim: `C-041`.
