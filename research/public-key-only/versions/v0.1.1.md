# v0.1.1 — ADVAPI first-use reductions
Date: 2026-08-09

## New findings
### F001 — no hidden initial RC4-key dimension
Reference user-mode `rc4_safe` allocates 8 entries but initializes every `BytesUsed` to `0xffffffff`, forcing a rekey before first output from each selected entry. Therefore arbitrary allocator residue in each initial RC4 key structure is overwritten before use on the normal first-use source path. The nominal 8-entry array does not add eight independent hidden initial keys.

Sequential selector order is `1,2,3,4,5,6,7,0,...`, so the easy "same entry reused immediately" hypothesis is also false under reference semantics.

### F002 — caller-buffer contribution is MD4-projected
Before user-mode RC4 selection/rekey/output, `RandomFillBuffer()` hashes the caller buffer through a circular hash configured as MD4. A 20-byte SystemFunction036 caller buffer therefore affects the circular-hash state through a 16-byte digest. For fixed prior state, the caller-buffer-induced next-state image is at most 2^128, not 2^160.

This is a genuine local dimensional reduction, but it does not bound the final RNG output below 128 because KSecDD/persistent state remains.

## New composition hypothesis
Within a single RSAENH `CryptGenRandom(64)` invocation, the same local aux20 slot appears to survive the loop from the first 40-byte block into the second 24-byte block. If exact shipped-binary SSA confirms no overwrite before the second SystemFunction036 call, only the first iteration introduces independent stack-prehistory for that local; the second caller-buffer input is recurrent state derived from the first iteration.

## Current effective model
`caller local B_t --MD4<=128--> circular hash C_t`
`C_t + KSecDD chain -> 256-byte rekey material -> selected ADVAPI RC4 entry -> SystemFunction036 R_t`
`R_t + RSAENH state -> XVAL_t (160 bits) -> out40`
