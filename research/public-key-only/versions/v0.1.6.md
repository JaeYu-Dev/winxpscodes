# v0.1.6 — Persistent KSecDD ratchet eliminates the independent-M-root model

Date: 2026-08-09

## New machine/state result
V24 SP3 trace/replay shows that KSecDD long-path rekeys are consecutive observations of one persistent 80-byte state trajectory.

Define:

`X_{t+1} = VLH(X_t, P_t)`

`M_t = C_t XOR KS_{X_{t+1}}[0:256]`.

The full 80-byte `X_{t+1}` is used as the cycle's second RC4 KSA key and then reused verbatim as the next cycle's first KSA key. Representative cycle boundaries were checked 80/80 bytes exactly; the V24 validator independently reports 16/16 KSA and 16/16 PRGA validations across eight cycles.

## Reachability model after composition
F007 gave the seven pre-first-key SystemFunction root sequence:

`[M1,M1,M2,M3,M4,M5,M6]`.

V17 caller-input analysis gave `C1..C8` as a deterministic startup family driven by at most two 128-bit MD4 digest roots `D1,D2`.

Therefore:

`(M1,...,M6) = Psi(X0, P1,...,P6, D1, D2)`.

This is a strict modeling improvement over counting six independent KSecDD secrets and six independent 256-byte caller buffers.

## What this does NOT prove
- `X0` is not assigned 640 bits of entropy merely because it is 80 bytes wide.
- `P1..P6` are not assumed independent.
- No `<2^128` first-private-key image/search bound has been proven.

## New main bottleneck
The Windows-side question has collapsed to the **fresh differential dimension of sequential gather inputs `P1..P6` plus the reachable image of initial state `X0`**.

The next audit must classify each gathered component/byte across consecutive startup cycles by exact provenance, not by heuristic entropy estimates.
