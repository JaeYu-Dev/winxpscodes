# F002 — SystemFunction036 caller-buffer contribution is projected through MD4 before rekey
Status: SOURCE-CONFIRMED / SHIPPED-SP3-VALIDATION-REQUIRED
PK-only effect: local dimensional reduction 160 -> <=128 bits per caller-buffer update; global break not proven.

## Source fact
In user-mode randlib, `RandomFillBuffer(pbBuffer, len)` calls:

`UpdateCircularHash(&g_CircularHashCtx, pbBuffer, len)`

**before** selecting/rekeying/outputting RC4. `InitRand()` configures this circular hash with `CH_ALG_MD4`, update increment 7, no feedback mode. `UpdateCircularHash()` computes MD4 over the complete caller buffer, then XORs the 16-byte MD4 digest into the 256-byte circular buffer and advances the circular position by 7.

Thus the caller's nominal 20-byte SystemFunction036 input does not enter the rekey dependency as 160 free bits. Its direct contribution is only:

`D_t = MD4(B_t)`

where `D_t` is 128 bits, followed by a deterministic XOR embedding into `CircBuf`.

## Cardinality bound
For a fixed prior circular-hash state `C_t`, the next state generated by varying a 20-byte caller buffer satisfies:

`|{ C_{t+1}(B) : B in {0,1}^160 }| <= 2^128`.

This is a strict machine/source-algebra projection from a nominal 160-bit caller buffer to a maximum 128-bit contribution.

## Important limitation
This does **not** imply the final SystemFunction036 output has <=128-bit support. The KSecDD/persistent-state rekey chain contributes additional hidden state, and consecutive caller-buffer digests may accumulate in the circular buffer.

## High-value composition hypothesis
The shipped SP3 RSAENH 64-byte loop reuses the same local `aux20` slot across its 40+24 iterations. The loop calls `SystemFunction036(aux20,20)`, then mixes caller-buffer bytes into that same local slot, consumes it in the FIPS block, and loops back without an obvious local reinitialization. If exact SSA confirms no intervening overwrite, the second SystemFunction036 input is not an independent stack-prehistory variable; it is a deterministic residue of the previous iteration.

That would reduce the count of independent caller-stack roots inside each CGR64 invocation.

## Shipped-binary obligations
1. Confirm ADVAPI32 SP3 still uses MD4 circular-hash projection before rc4_safe output.
2. Confirm 16-byte digest width and 256-byte circular state.
3. Confirm RSAENH D640 second iteration reaches SystemFunction036 with the previous aux20 residue as input, with no first-writer between loop-back and the call.

## Falsifier
A shipped SP3 path in which caller bytes bypass MD4 and enter the RC4 key/state directly, or in which D640 reinitializes aux20 before each SystemFunction036 call, kills the corresponding reduction.
